# Web search reference

Use [tools](../guides/tools.md) for the complete built-in tool overview and
[permissions](../guides/permissions.md) for authority and network boundaries.

## Provider-hosted web search

Native `web_search` is enabled by default on the official OpenAI Responses (API key and subscription), Anthropic Messages, and xAI Responses endpoints. The adapter checks the endpoint, not the model name or credential type. Compatible custom gateways are opt-in. OpenAI subscription defaults use cached search (`external_web_access=false`); explicit selection retains live access (`true`). Anthropic and xAI native search use live access. Offering the tool does not prove model support or account entitlement. Explicit native selection on API and OAuth connections uses the resolved provider's hosted search contract and model credential. It does not need `EXA_API_KEY`. An explicit `--tools` list must include `web_search` to keep it; `--no-tools` disables tools. A model or connection switch reevaluates native support but never substitutes an independent search recipient. Hosted search shares the authority to use the selected provider, with no separate consent prompt. Pricing follows that route; API routes are not presumed free. Ego sends a budget of five as `max_tool_calls` on OpenAI API Responses (a hosted-tool call limit) and `max_uses` on Anthropic Messages (a search-use limit, for both API key and OAuth). Those two limits are provider-enforced. xAI Responses sends the same budget as `max_turns`, a limit on agentic tool-calling turns, not individual searches. On OpenAI subscription, Ego closes the response stream when it observes a distinct web-search call beyond that budget, at the start if visible or at completion otherwise. Only items whose action is a search count, once each; page opens and in-page finds do not, and a start without an action is not counted until its action is known. The stop exits with the budget code (5). This can end the generation before the final answer, citations, or usage arrive. Both routes are best effort for individual searches: the server may already have dispatched or charged for additional work. The budget is not a monetary limit. The monetary cap checks recorded known response spend before admitting another request; it does not reserve a worst-case search charge. Unknown costs remain unknown, and an admitted request can cross the cap. See [cost accounting](../guides/providers.md#capability-and-cost-facts).

Default composition removes the independent Exa adapter, even on non-native routes with `EXA_API_KEY` configured. Explicit `--tools web_search` is native-only. If the resolved model cannot use native search, ego omits that declaration; a rejected native request reports the provider error. Neither case selects Exa.

Configured Moonshot Responses and Mistral Conversations models also offer native search by default on their official endpoints. Z.ai Chat offers explicit native search, but its published stream schema does not define search sources or a search count. DeepSeek Chat offers explicit native search only when no local function tools are declared. It refuses a mixed request rather than dropping functions; `--tools web_search` selects built-ins and does not remove attached MCP tools.

Use `--tools web_search_external` to select the independent Exa adapter. It requires `EXA_API_KEY`, `allow_paid=true` on each call, and ordinary network permission. The external selector never enables provider-hosted search. Model changes, retries, children and session resume keep the selected tool name; they do not exchange recipients or credentials. Existing configurations that used `web_search` for Exa must select `web_search_external` explicitly. No compatibility alias is provided. Selecting both names explicitly exposes two distinct tools, not a fallback chain. Provider-private search history cannot be silently replayed to another provider.

Search activity appears as reasoning progress. Cited sources appear as links in the assistant output, including the ACP assistant-content stream. Private provider content is kept in durable history for continuation but is excluded from public events and redacted exports. Anthropic `pause_turn` continues the provider's server-tool loop with the preserved content; it does not invoke a local tool.

The offline fixtures come from published provider examples. No live search conformance or per-model availability is claimed by these fixtures.
